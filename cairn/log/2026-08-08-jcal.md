# jCal, RFC 7265

`src/jcal.rs` behind the `jcal` feature, with `serde_json` as its only dependency and a raw `Value` at the boundary. `Ical::to_jcal` writes, `Ical::from_jcal` reads back and borrows the JSON tree's strings.

The interesting half is the type slot. jCal puts a property's value type where iCalendar puts a `VALUE` parameter, and the naive reading of that (take the slot, look it up, done) loses information in both directions. Import therefore resolves the slot through the same property spec the wire decoder uses, and export writes the declared kind rather than the model's own: `RDATE;VALUE=PERIOD` goes out as `period`, which is what the RFC's examples show, and comes back with its parameter. A slot that says no more than the property's default is dropped on the way in, so nothing is invented either.

That work turned up a modelling bug on the way. `CATEGORIES;VALUE=TEXT:one,two` decoded to the single text `one`, because the spec honoured the declared `TEXT` and dropped the list: the declared kind describes each *item*, not the value as a whole. `CATEGORIES` and `RESOURCES` now pin their list kind the way `RDATE` and `EXDATE` do, which fixes the wire decoder as much as the codec.

Round-tripping is stated as a fixpoint, not as byte equality, because three things a JSON document cannot hold are normalised: parameter order, recurrence rule part order, and the case of an unknown name (jCal lowercases every name; iCalendar's convention is uppercase, and that is what import restores). The tests assert the fixpoint over the six RFC fixtures and over a calendar carrying every value kind the model has, and assert the exact JSON of a small calendar against the shape RFC 7265 defines, so the format is the RFC's rather than a paraphrase of it.

Integers go out as integers. `serde_json::Number::from_f64` turned `PRIORITY:5` into `5.0`, which is the same number to JSON and a different one to every reader.

The `jcal` feature implies `parser`, since resolving a type slot means reading the property spec, which lives under `tree`.

Capabilities moved: `jcal` (ADDED: jCal codec, what jCal normalises).
